# Work Log · August 11, 2026 (Tuesday)

**Hours:** ~4.5

## Overview

First tool of Wave 5: a unit converter. Pick a category (length, mass, temperature, area,
volume, speed, data), choose from/to units, and convert. Bread-and-butter utility, but with a
couple of details worth getting right.

## Today's Work

### 1. An i18n Shortcut Worth Noticing

Unit *symbols* are language-neutral — `km`, `kg`, `°C`, `mph`, `GiB` are written the same in
English and Chinese. Only the **category names** (Length / 长度) need translating. So I put
the conversion data (symbols + factors) in a plain `lib/units.ts` module with no translation
at all, and the UI only pulls category names from the message catalogue. That kept a
seven-category, ~45-unit converter almost entirely out of the translation files.

### 2. Linear Factors vs. Affine Temperature

Most units convert through a single base factor: store each unit's ratio to a base (metre,
gram, litre…), then `value × fromFactor ÷ toFactor`. Clean and uniform. **Temperature is the
exception** — Celsius/Fahrenheit/Kelvin are *affine*, not linear (they have different zero
points), so a single multiply is wrong. `100°C` isn't `100 × something °F`. I special-cased
it: convert to Celsius, then out to the target, with the real offset formulas. The tell-tale
test is −40°C = −40°F (the one temperature where the scales cross); it passes.

### 3. Verification

Unit-tested the conversions in isolation before the UI — the ones people actually sanity-check
a converter against: 1 mile = 1.609344 km, 12 in = 30.48 cm, 1 kg = 2.2046 lb, 100°C = 212°F,
32°F = 0°C, −40 crossover, 1 ha = 10000 m², 1 GiB = 1024 MiB (binary, not decimal). All pass.
Then lint + build (69 pages) and both locales served correctly, category names translated,
listed under Calculators and on `/tools`.

## Outcome

Wave 5 is underway. The keeper is the modelling distinction: unit conversion is uniform *until*
it isn't — temperature's affine scales need real formulas, not a factor, and the −40 crossover
is the test that catches a lazy implementation.
