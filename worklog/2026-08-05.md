# Work Log · August 5, 2026 (Wednesday)

**Hours:** ~4.5

## Overview

Third tool of Wave 3: a cron-expression explainer. Cron syntax (`*/15 9-17 * * 1-5`) is
compact and easy to misread, so a tool that breaks it into a plain, field-by-field
description is genuinely useful — nobody remembers whether the fifth field is 0- or 1-indexed
for Sunday.

## Today's Work

### 1. A Deliberate Choice: Field Table, Not a Fluent Sentence

Most cron explainers produce a sentence like "At every 15th minute past hours 9 through 17,
Monday through Friday." That reads nicely in English — but this site is bilingual, and
generating grammatical, natural sentences in *two* languages from parsed parts is a real
translation project with lots of ways to sound wrong. So I chose a **field-by-field table**
instead: each of the five fields (minute, hour, day-of-month, month, day-of-week) on its own
row, with the raw token and a short description of its value. It's honest, unambiguous, and
translates cleanly because each piece is small and self-contained. Choosing the presentation
that i18n can actually support well was the main design decision.

### 2. The Parser

Each field is parsed independently against its own valid range (minute 0–59, hour 0–23, and
so on). Within a field I support the real cron vocabulary: `*` (every), `*/n` (step), `a-b`
(range), `a-b/n` (stepped range), comma lists, and single values — recombined by joining the
parts. Anything that doesn't fit, or a number out of range, marks that one field invalid
rather than failing the whole expression, so you can see exactly which field is wrong.

### 3. Names, Not Just Numbers

My first version only accepted numbers, and testing immediately showed the gap: `5 4 * * SUN`
and `0 9 * * MON-FRI` are perfectly valid cron and extremely common, but came back invalid.
So I added a normalization step that maps the three-letter month and weekday names to their
numbers before parsing, which lets the existing numeric logic handle ranges and lists of
names for free. Also handled the quirk that the weekday field accepts both 0 and 7 for
Sunday. Re-tested: `SUN`, `MON-FRI`, `JAN,JUL`, and `7` all resolve correctly now.

### 4. A Comment That Broke the Build

A silly but instructive one: my doc-comment for the parser included the example `"*/15"`, and
the `*/` inside it **closed the block comment early**, producing a parse error the build
caught. Reworded the comment to avoid the literal `*/`. A good reminder that `*/` is never
just text inside a `/** ... */` comment.

### 5. Verification

Unit-tested the parser across a spread of expressions — steps, ranges, lists, month/weekday
names, the 0-or-7 Sunday case, and out-of-range and wrong-field-count errors — before wiring
the UI. Then lint + build (55 static pages) and both locales served correctly, listed under
Developer and on `/tools`.

## Outcome

Wave 3 has three tools. The theme was matching the output format to what internationalization
can support: a field table beats a fluent sentence when the sentence has to be correct in two
languages. And a reminder that cron's real-world syntax includes names, not just the numbers
the textbook examples use.
