# Work Log · July 27, 2026 (Monday)

**Hours:** ~4.5

## Overview

First day of the front-end restructure. With twelve tools now, the home page is one long
scroll, and there's no way to jump to a kind of tool. Today I built the backbone of the fix:
per-category pages and a category dropdown in the navbar, so the site is navigable by type.
This is deliberately not a new tool — it's infrastructure so the library can keep growing
without the front page falling apart.

## Today's Work

### 1. Deciding: Category Pages, Not Pagination

I settled this during planning, but it was worth being clear about while building. A tools
site is browsed by *kind* — "I want a color tool" — not by page number. So the structure is
category pages (`/c/encode`, `/c/generate`, …), each its own URL, rather than "page 2 of 3".
Each category page is independently indexable, which is good for international SEO: search
engines now have a `/en/c/generate` and `/zh/c/generate` to rank, not just a monolithic home
page.

### 2. Building on the Registry

The nicest part was how little new data this needed. Back during the i18n work I made
`lib/tools.ts` hold pure structure — slug, href, icon, category key. Today I added three
small helpers on top of that: the ordered list of categories, the tools within a category,
and a type guard for validating a category slug from the URL. Everything else — names,
descriptions, category labels — already lives in the message catalogues, so the category
pages are fully bilingual for free.

### 3. The Category Pages

`app/[locale]/c/[category]/page.tsx`, with:

- `generateStaticParams` returning every category, so each is pre-rendered per locale (43
  static pages now, up from 31).
- A `notFound()` guard via the type guard, so `/c/nonsense` correctly 404s rather than
  rendering an empty page — I verified that returns a real 404.
- Localized metadata (the category name in the `<title>`) and a breadcrumb back to home.
- A live tool count using an ICU plural (`{n, plural, one {# tool} other {# tools}}`) on the
  English side — the first time I've needed pluralization, and next-intl handles it in the
  message rather than in code.

### 4. The Navbar Dropdown

Replaced the single "All Tools" link with a categories dropdown (a small client component).
It closes on outside click and on Escape, and marks itself up with `aria-haspopup` /
`aria-expanded` / `role="menu"` for accessibility. The category links render when the menu
opens; the tools themselves remain listed on the home page and every category page is in the
sitemap, so nothing depends on the dropdown for discoverability — it's a convenience layer
on top.

### 5. Sitemap

Extended the sitemap generator to include the six category pages, each with its en / zh /
x-default hreflang alternates. It's generated from the same `categories` helper, so it can't
drift from the actual set of categories. Verified: 19 URLs (home + 6 categories + 12 tools),
each with proper alternates.

## Outcome

The site is now navigable by category: a dropdown to jump straight to a kind of tool, and a
dedicated page per category that search engines can index on its own. No tool was added, but
the structure to keep adding them is in place. Twelve tools no longer means one endless page.
