## Completed Work

- Added `/json-flatten` with two explicit modes: nested JSON to a flat map and flat map back to
  its original JSON structure.
- Used canonical RFC 6901 JSON Pointer keys. Property names containing `/` and `~` are escaped as
  `~1` and `~0`; empty property names remain representable.
- Added an explicit marker for every object and array, including the root at the empty pointer.
  This preserves empty containers and distinguishes arrays from objects whose keys happen to be
  numeric. Root primitives are also supported.
- Rebuilt arrays from out-of-order entries while rejecting leading-zero, negative, dash, oversized
  and nonnumeric indexes. Sparse arrays are rejected instead of silently inserting `null` values.
- Rejected malformed pointers, missing root/parent markers, nonempty structural markers, primitive
  parent conflicts and maps exceeding the supported limits.
- Protected object reconstruction from prototype pollution: keys such as `__proto__` are defined
  as ordinary own data properties without changing object prototypes.
- Limited input to 2,000,000 characters, nesting to 100 levels, flattened output to 5,000 entries
  and array indexes to the bounded entry range.
- Added English and Chinese UI, examples, mode-specific labels, copy/clear actions, accessible
  error states, Developer-category registration, metadata, structured data and sitemap coverage.

## Learning Notes

- Leaf-only flattened maps cannot reliably distinguish arrays from objects with numeric keys and
  cannot retain empty containers. Explicit container markers make the representation reversible.
- JSON Pointer describes path tokens but not container types; `~0` and `~1` must be decoded in the
  standard order so literal tildes and slashes round-trip correctly.
- Reconstructing objects with ordinary bracket assignment can treat `__proto__` specially.
  Defining own data properties avoids prototype mutation while preserving the original key.
- Validating sparse indexes before accepting the result avoids hidden holes and large-index memory
  abuse in browser arrays.
