# Work Log · August 13, 2026 (Thursday)

**Hours:** ~4.5

## Overview

A meatier Wave 5 tool: a live markdown preview — markdown source on the left, rendered HTML on
the right, updating as you type. I chose to hand-write a small renderer rather than pull in a
markdown library, both to keep the dependency surface small and because the interesting part —
rendering untrusted input safely — is exactly what I'd want to understand rather than delegate.

## Today's Work

### 1. The Security Model Comes First

Rendering markdown means producing HTML and injecting it with `dangerouslySetInnerHTML`. If I
just transformed the source, anyone could type `<script>` or `<img onerror=…>` and it would
execute. So the very first step of the renderer is to **escape all HTML** (`< > & "`) in the
source. Only *after* that does markdown syntax get applied, to the already-escaped text. Any
tags the user typed are now inert text; the only HTML in the output is what my renderer
generated. I also restricted links to safe URL schemes (http/https/mailto/relative/anchor), so
`[x](javascript:alert(1))` stays literal text instead of becoming a live link.

I verified the holes are closed before building the UI: `<script>alert(1)</script>`,
`<img src=x onerror=…>`, and a `javascript:` link all come out neutralized.

### 2. Escape-First Has a Catch

Escaping first is correct for safety but broke a feature: blockquotes. The blockquote marker
is `>`, which my escape step turns into `&gt;` — so `/^>/` never matched and `> quote` rendered
as a literal paragraph. The fix was to detect the *escaped* marker (`/^&gt;/`) instead. A neat
illustration that "escape everything up front" interacts with any syntax that reuses HTML's
special characters — you have to match what the text actually looks like after escaping.

### 3. The Renderer

A line-based parser covering the common subset: headings, bold/italic/inline-code, fenced code
blocks (whose contents are shown verbatim, still escaped), links, ordered/unordered lists,
blockquotes, horizontal rules and paragraphs. Fenced code blocks are handled with a mode flag
so their insides aren't re-parsed as markdown.

### 4. Making It Look Like Markdown

One CSS gotcha: Tailwind's reset flattens `h1`, `ul`, etc. to plain text, so the rendered
preview looked unstyled. Since the HTML is generated (not JSX I can put classes on), I added a
small scoped stylesheet targeting `.md-preview h1`, `.md-preview ul`, and so on, to restore
sensible heading sizes, list bullets, code backgrounds and blockquote borders.

### 5. Verification

Unit-tested the renderer (elements + the three injection attempts + the blockquote fix), then
lint + build (73 static pages) and both locales served — translated labels, no leakage, Text
category now at five tools, and the sample document renders server-side.

## Outcome

The standout lesson: when you render untrusted input, escape first and let the syntax layer
work on the escaped text — and then remember that your own block syntax (`>`) now looks
different too. Hand-writing it made that trade-off explicit in a way a library would have
hidden.
