# Work Log · August 25, 2026 (Tuesday)

**Hours:** ~4.5

## Overview

Today's tool was **Remove Duplicate Lines**, a practical text-cleanup utility from the original
Phase 1 backlog. Paste a list, remove repeated lines, keep the first occurrence, and copy the
cleaned result. Small feature, but exactly the kind of everyday internet tool ToolNest is meant
to collect. This is the 30th tool.

## Today's Work

### 1. Behaviour Before UI

The main behaviour decision: removing duplicates should keep the **first** occurrence, not sort
or rearrange the list. If someone pastes a priority list, a CSV column, a set of notes or search
keywords, order can matter. So the tool walks top to bottom, remembers what it has already seen,
and preserves the earliest copy.

Added three options: case sensitive on/off, trim whitespace before comparing, and keep or remove
blank lines. The default is forgiving: ignore case, trim before comparing, and drop blank lines.
That handles the common messy-list case where `Apple`, `apple` and `  Apple  ` are really the
same item.

### 2. Shared Line Module

Rather than bury the logic inside the page, I added `lib/lines.ts`. The first export,
`removeDuplicateLines`, returns the output plus counts for kept and removed lines. That makes the
UI simple and gives the user immediate feedback: how many lines were kept and how many were
removed.

The module normalizes CRLF and lone CR to LF internally, so text copied from Windows, old files or
web forms behaves the same way. Empty input is treated as zero lines, not one blank line — a small
edge case that would look silly on the first load if ignored.

### 3. Tests

Added `lib/lines.test.ts` alongside the module. For the duplicate-removal half, the tests cover
keeping the first occurrence, case-insensitive matching, whitespace-trimmed matching, dropping
empty lines, and empty input returning zero kept and zero removed.

This is simple code, but it is also the kind of simple code that tends to grow options. Having the
tests in place means the text sorter can reuse the module tomorrow without guessing whether the
shared logic still behaves.

### 4. Page and Product Fit

Built `/remove-duplicates` under the Text category. It follows the ToolNest pattern: options at
the top, one textarea for input, one readonly textarea for output, and a copy button. Added
English and Chinese messages, metadata layout, JSON-LD, registry entry and an example button.
Because the registry drives the navigation, the new page automatically appears on the home search,
the full tools list, the Text category page and the sitemap.

## Outcome

30 tools now. The useful lesson was that even a tiny text tool benefits from a precise default:
keep order, keep the first copy, and treat messy whitespace/case as duplicates unless the user asks
for stricter comparison.
