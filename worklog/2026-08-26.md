## Today's Work

### 1. Sorting Is Mostly About Options

The basic version is easy: split by line, call `sort`, join the lines. The useful version needs
the choices people actually expect: ascending or descending, case-sensitive or case-insensitive
comparison, numeric sort, trim whitespace before sorting, and remove duplicates before sorting.

The default is alphabetic ascending, case-insensitive, with whitespace trimmed for comparison.
That matches how someone cleaning a list of words, emails or keywords usually expects it to work.

### 2. Reusing `lib/lines.ts`

Extended yesterday's line module with `sortLines`. It reuses the same normalization choices and
the same duplicate-removal helper when that option is enabled. Numeric sorting uses number
comparison when both lines are finite numbers, and otherwise falls back to locale-aware string
comparison with the `numeric` option enabled. That means mixed lists still behave reasonably
instead of throwing away non-number lines.

I kept the original line text in the output. Trimming affects comparison, not the user's content,
which is less surprising: if someone pasted an indented list, sorting should not silently delete
their indentation unless the tool explicitly says it is formatting text.

### 3. Tests

Expanded `lib/lines.test.ts` for the sorter: ascending and descending alphabetical order, numeric
order (`1`, `2`, `10`), optional duplicate removal before sorting, and empty input staying empty
with zero lines. This brought the full test suite to 54 tests.
