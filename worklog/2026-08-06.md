## Today's Work

### 1. The Algorithm: Longest Common Subsequence

A diff is fundamentally the longest-common-subsequence problem. The lines both versions share,
in order, are the "unchanged" backbone; everything in the original but not in that backbone
was removed, and everything in the changed version but not in it was added. I implemented the
classic dynamic-programming LCS over the arrays of lines: fill an (n+1)×(m+1) table of
common-subsequence lengths, then backtrack from the top-left, emitting an unchanged line when
the two current lines match and otherwise stepping in the direction the table says preserves
the longer subsequence — a deletion or an addition.

The reason to use LCS rather than a naive line-by-line compare is minimality: LCS produces the
*smallest* set of changes. Insert one line into the middle of a file and a naive compare
reports everything after it as changed; LCS reports exactly one addition. I verified that
property directly — inserting a line into a 60-line file yields one addition and zero spurious
deletions.

### 2. Verifying Before the UI

Tested the diff on the cases that distinguish a correct implementation from a plausible one:
inserting a line in the middle (one `+`, nothing else), deleting a line (one `-`), a changed
line (one `-` and one `+`), identical inputs (all unchanged), and the 60-line single-edit case
for minimality. All came out right.

### 3. An Empty-Side Edge Case

Testing turned up a cosmetic bug: an empty Original side split into a single empty string, so
comparing "" against real content showed a spurious "deleted blank line" before the additions.
The fix was to treat a wholly-empty side as *zero* lines rather than one blank line — while
still keeping genuine trailing blank lines (from a trailing newline) intact. Small, but it's
the difference between the tool looking correct and looking slightly broken on the first thing
someone might try.

### 4. Presentation

Two side-by-side inputs, and below them a unified diff: unchanged lines dimmed, additions on a
green background with a `+`, deletions on red with a `-`, and a header summarizing the counts
("3 additions · 1 deletion", pluralized properly). Identical inputs say so explicitly instead
of showing an empty result. I filed it under the Text category rather than Developer — a diff
is as useful to a writer comparing drafts as to a developer — which also balances the category
sizes a bit.
