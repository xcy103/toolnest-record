# Work Log · September 1, 2026 (Tuesday)

**Hours:** ~4.5

## Overview

Today's task was the **BMI Calculator**, the second everyday calculator in this batch. It calculates
adult body mass index in metric or US/imperial units, classifies the result into the standard
screening ranges and keeps every calculation in the browser. This brings ToolNest to 35 tools.

## Today's Work

### 1. Formula, Units and Scope

Implemented both common formulas: kilograms divided by metres squared, and the customary imperial
formula using pounds, inches and the factor 703. The unit control converts the values already in
the fields, so switching systems does not make the user enter the same measurements again.

The page is deliberately scoped to adult BMI screening. It shows underweight, healthy weight,
overweight and obesity ranges, but it also states that BMI is not a diagnosis and does not account
for factors such as age, pregnancy, muscle mass or individual medical history.

### 2. Pure Logic and Boundary Tests

Extended the shared everyday-calculator module with metric and imperial BMI functions plus a
category function. Tests cover invalid zero measurements and the exact category boundaries at
18.5, 25 and 30. The first test run also exposed the small expected difference caused by the
imperial formula's rounded factor of 703, so the test now verifies the customary formula directly
instead of demanding false precision against the metric result.

### 3. Bilingual Interface and Metadata

Built `/bmi-calculator` with metric and imperial controls, numeric height and weight fields, a live
one-decimal result and translated category text. Added bilingual descriptions, metadata, JSON-LD
and registry wiring, which makes the page available throughout navigation, search and the sitemap.

### 4. Browser QA and Precision Fix

The production browser check found a subtle interaction issue: unit conversion initially rounded
the field values to one decimal place. That made a BMI of 22.9 briefly display as 22.8 after
switching to imperial, even though the formula was correct. I changed converted measurements to
retain three decimal places. A second browser run confirmed that 70 kg / 175 cm stays at 22.9 after
conversion to 154.324 lb / 68.898 in, with no console errors.

Final checks: 72 tests passing, lint clean and a successful production build with 99 static pages.

## Outcome

35 tools are now live in the codebase. Today's main lesson was that unit conversion is part of the
product behaviour, not just display formatting: rounding intermediate inputs can visibly change a
correct answer and weaken trust in the calculator.
