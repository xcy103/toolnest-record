# Work Log · August 17, 2026 (Monday)

**Hours:** ~4.5

## Overview

With the wave plan finished, today was the step back I promised myself: a polish day rather
than a new tool. The site had 26 working tools and exactly one page title between them — every
tool page inherited the site default. So this was an SEO and metadata pass: real per-page
titles, descriptions, canonicals, hreflang and Open Graph tags, structured data for search
engines, plus a couple of genuine narrow-screen layout fixes found along the way.

## Today's Work

### 1. Why Client Components Have No Metadata

The morning's reading was Next's metadata API, and it explained a problem I had shipped without
noticing. Metadata — the `metadata` object and `generateMetadata` — is **Server Component only**,
because the head tags have to be resolved on the server before the page renders. Every one of
my tool pages is `"use client"` (they all have interactive state), so none of them could export
metadata at all. The site framework and category pages had proper titles; the 26 tools, the
pages that actually get searched for, were all titled "ToolNest · Free Online Tools".

The fix is the pattern the docs recommend: keep the interactive part a Client Component and put
the metadata in a **Server Component wrapper**. I chose a small `layout.tsx` per tool directory
rather than restructuring 26 pages into server-wrapper + client-body pairs — it's the smaller,
less invasive change, and the shared logic lives in one helper anyway.

### 2. One Helper, Twenty-Six Thin Layouts

`lib/metadata.ts` holds everything that varies by page: the title (the tool's registry name),
the description (each page's own longer blurb — it reads better as a search snippet than the
short card text), the canonical URL, hreflang alternates for both locales plus `x-default`, and
the Open Graph / Twitter block. A slug-to-namespace helper turns `word-counter` into
`wordCounterPage`, so a tool only ever names itself once.

Each tool layout is then about ten lines: read `locale` from `params`, hand the slug to the
helper, render the children. Boilerplate, but honest boilerplate — Next resolves metadata per
route segment, so a per-route file is the price of entry.

One thing that bit me: **Next replaces the parent's `openGraph` rather than merging it**. My
category pages set only `openGraph.url` and silently lost `og:type` and `og:site_name` from the
root layout. Shallow merge at the top level, full replacement inside. I pulled the shared fields
into an `openGraphFor(path, locale)` helper that every page spreads in.

### 3. Structured Data

Then JSON-LD, following Next's guide: render the payload as a `<script type="application/ld+json">`
in the layout. Each tool describes itself as a schema.org `SoftwareApplication` — category
"UtilitiesApplication", operating system "Any (web browser)", free, with the publisher attached
— and the home page carries a `WebSite` entry. The guide's security note is a good one and I
took it: `JSON.stringify` does not escape `<`, so a stray tag in the payload could close the
script element. Replacing `<` with its unicode escape on the way out costs nothing.

### 4. Narrow Screens

The responsive half was smaller than I expected, because the layouts have been mobile-first from
the start, but two real problems turned up. Tool panel headers put a label and its buttons in a
`justify-between` row with no wrapping, which overflows at 320px when the buttons are wide (the
password generator has two). And in the gradient editor, the range slider sits in a row with a
colour swatch, a hex field, a percentage and a delete button — but a flex item defaults to
`min-width: auto`, so the slider **refuses to shrink below its intrinsic width** and pushes the
row past the viewport. `min-w-0` on the slider and a narrower hex field on small screens fixed
it. That min-width default is worth remembering: `flex-1` alone does not mean "shrinkable".

### 5. Verification

Built (77 static pages, unchanged), then served the production build and inspected the real HTML:
all 26 English tool pages now have **26 distinct titles**, each with its own description,
canonical, three hreflang links and a full Open Graph block, in both locales — the Chinese pages
carry Chinese titles and `og:locale=zh_CN`. Lint and types clean.

## Outcome

The site is no longer invisible to search engines below the home page: every tool, category and
directory page identifies itself properly, in two languages, with the translations linked to one
another. Two lessons stuck — metadata is a server-side concern, and Open Graph blocks replace
rather than merge.
