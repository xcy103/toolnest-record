# Work Log · August 31, 2026 (Monday)

**Hours:** ~4.5

## Overview

Today's task was the **Percentage Calculator**, the first of the small everyday calculators left
in the backlog. The goal was not a single “percent of” field, but one focused page that answers
the three percentage questions people most often need. This brings ToolNest to 34 tools.

## Today's Work

### 1. Defining the Three Calculations

The page supports three modes: finding a percentage of a number, finding what percentage one
number is of another, and calculating percentage change from a starting value to a final value.
Keeping these as explicit modes makes the labels change with the question, so users do not need
to remember which number belongs in which field.

The zero cases needed a deliberate rule. A part cannot be expressed as a percentage of a zero
whole, and percentage change from zero has no finite answer. The tool reports that the input is
invalid instead of showing `Infinity` or inventing a value.

### 2. Shared Calculation Module and Tests

Added `lib/everyday-calculators.ts` for the pure calculation functions and result formatting. This
keeps formulas out of the React page and makes the edge cases easy to test. Tests cover positive
and negative values, increasing and decreasing changes, zero denominators and floating-point
formatting.

### 3. Bilingual Page and Site Wiring

Built `/percentage-calculator` with a three-option mode control, labelled numeric inputs, a live
result and copy support. Added English and Chinese text, tool metadata, JSON-LD and the registry
entry. The existing registry automatically exposes it in search, the Calculators category, the
all-tools page and the bilingual sitemap.

### 4. Verification

Ran the full unit suite, lint and production build. I also tested the production page in a real
browser: switching to percentage change and entering 80 to 100 correctly returned 25%, with no
console errors. A narrow mobile viewport confirmed that the controls stack cleanly.

## Outcome

ToolNest now has 34 tools. The useful lesson today was that a very small calculator still benefits
from carefully named modes and explicit invalid states; those details remove more confusion than
adding more formulas would.
