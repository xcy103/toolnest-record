## Overview

Back to building tools: a JSON ↔ CSV converter, the obvious neighbour of the JSON formatter

optional type detection. The 27th tool.

## Today's Work

### 1. Learning: CSV Is Not "Split on Commas"

The morning went into RFC 4180, and it was worth the time. CSV looks like the simplest format
in the world until you notice that a field may legally contain the delimiter, a double quote, or
**a line break** — as long as the field is quoted, and as long as inner quotes are doubled
(`""`). So `a,"x,y",1` is three fields, not four, and a quoted field can span several physical
lines while still being one cell. Any converter built on `text.split(",")` is wrong the first
time someone exports an address or a comment field.

That ruled out a regex and pointed at a small **character-by-character state machine** with one
piece of state: am I inside quotes? Inside, everything is literal except `"`, which either
escapes itself when doubled or ends the field. Outside, the delimiter ends a field and a
newline ends a record. Line endings needed care too — real-world files arrive with LF, CRLF and
occasionally a lone CR, so the parser treats CRLF as a single ending rather than emitting a
phantom empty row.

### 2. The Library: `lib/csv.ts`

I kept the whole conversion in a plain module with no React in it, the same shape as `lib/calc.ts`
and `lib/units.ts`. Three exported functions: `parseCsv` (text → rows of raw fields), `csvToJson`
and `jsonToCsv`.

Design decisions worth recording:

- **Columns are the union of the keys**, in first-seen order. Real JSON arrays are not always
  uniform; a row missing a key gets an empty cell rather than an error.
- **Nested values keep their JSON form.** A cell can't hold an object, so `{"x":1}` is written
  as JSON text and quoted. Lossy in spirit, but predictable — and it survives the round trip as
  a string rather than silently disappearing.
- **Quote only when necessary**: if a value contains the delimiter, a quote, a newline, or has
  leading/trailing spaces (which spreadsheets otherwise eat).
- **Type detection is opt-in and deliberately conservative.** `36` becomes a number, `true` a
  boolean, `null` a null — but `007` stays a string, because turning a zip code or an order
  number into `7` is the classic spreadsheet crime. Only plain JSON-style numbers convert.
- Errors are **identifiers, not sentences** — `csvRagged` with the line number, expected and
  actual field counts, `csvUnclosedQuote` with the line the quote opened on. The page turns them
  into English or Chinese. Same rule as the calculator: the library states the fact, the UI
  chooses the words.

### 3. Testing Before UI

I wrote the tests first this time and ran them straight on the module with Node's TypeScript
stripping — 31 cases: quoted delimiters, doubled quotes, embedded newlines, CRLF and lone CR,
blank lines, all three delimiters, the ragged-row and unclosed-quote errors, key-union ordering,
null and missing values, and a **full round trip** of an array containing a comma, an escaped
quote and a multi-line field, which came back byte-identical after JSON → CSV → JSON.

One small find: Node's strip-only TypeScript mode rejects constructor **parameter properties**
(`constructor(public readonly key: …)`), which is what my earlier error classes use. Writing the
error class the long way — declare the fields, assign them in the body — cost two lines and made
the module directly testable without a build step. I'll take that trade.

### 4. The Page

`app/[locale]/json-csv/page.tsx` follows the house pattern: a direction toggle, a delimiter
select, two CSV-only checkboxes (header row, type detection) that hide when converting the other
way, input and output panels with a copy button. Switching direction feeds the output back in as
the new input, so a conversion can be checked by reversing it — the same trick the Base64 page
uses. There's an "Example" button because a JSON-array-of-objects is easier to show than to
describe, and a row count under the result. Both locales, and the new metadata layout from
yesterday gives it its own title, description and structured data for free.

## Outcome

27 tools. The library half is genuinely solid — a real RFC 4180 parser with tests to prove it —
and the lesson I want to keep is that "obviously simple" formats usually aren't: quoting rules
are where CSV hides its complexity, and a 60-line state machine handles them all far more
honestly than any regex I could have written.
