# Work Log · August 19, 2026 (Wednesday)

**Hours:** ~4.5

## Overview

An infrastructure day, and an overdue one. I've been writing tests for the trickier logic —
the expression evaluator, the MD5 implementation, the colour maths, yesterday's CSV parser —
but every one of them was a throwaway script in a temp folder, run once and deleted. Nothing
in the repository could tell me whether any of it still worked. Today I gave the project a real
test suite: `npm test`, checked in, covering every pure-logic module.

## Today's Work

### 1. No New Dependency

The obvious move is to install Jest or Vitest. I didn't, for the same reason the site has almost
no runtime dependencies: Node now ships a test runner (`node:test`) and a TypeScript loader, so
`node --test lib/*.test.ts` runs typed test files directly with nothing installed and nothing to
configure. `npm test` is now one line in `package.json`, and there is no test framework to keep
up to date.

Two small frictions came with that, both worth knowing:

- Node's TypeScript support is **strip-only** — it removes types, it does not compile. So the
  imports need the real file extension (`./calc.ts`), which TypeScript itself rejects unless
  `allowImportingTsExtensions` is on. One tsconfig line, and both tools agree.
- Strip-only also refuses **constructor parameter properties**. `CalcError` was written as
  `constructor(public readonly key: …)`, which meant the calculator — the module with the most
  intricate logic on the site — could not be imported by a test at all. I rewrote the class the
  long way: declare the fields, assign them in the body. Same behaviour, four extra lines, and
  the module became testable. (I hit this same wall yesterday with the CSV error class and fixed
  it there without registering that the older modules had the same problem.)

### 2. What Got Covered

Six modules, 34 tests to start with:

- **calc** — precedence, right-associative exponentiation, unary minus, functions and
  constants, factorial, degree mode, and every error identifier the UI knows how to display.
- **md5** — the RFC 1321 reference vectors. This is hand-written code (Web Crypto has no MD5),
  so these five strings are the only thing standing between the tool and a silently wrong hash.
  Plus the 55/56-byte cases, which straddle the block-padding boundary.
- **colour** — hex parsing (long and short form), RGB↔HSL round trips, and the WCAG numbers:
  black-on-white is exactly 21, a colour against itself is exactly 1, and #767676 on white sits
  just above 4.5, the AA threshold.
- **units** — linear conversion, the affine temperature cases (100 °C = 212 °F, −40 crossing),
  and a structural check that every category has at least two units with no duplicate symbols.
- **markdown** — the block and inline rendering, and the security properties: raw HTML comes
  back escaped, and a `javascript:` URL stays plain text instead of becoming a link.
- **csv** — yesterday's 31 cases, finally living in the repo.

### 3. A Small Truth the Tests Told Me

One assertion failed immediately, and it was mine that was wrong, not the code: converting
12 inches to feet gives `0.9999999999999998`, because the conversion goes through a base unit and
two floating-point divisions don't cancel exactly. Nothing to fix — `formatResult` already
trims that to `1` before it reaches the screen — but the test now asserts the *displayed* value
and carries a comment explaining why. That's a better test than the one I meant to write: it
documents the division of labour between the maths and the formatting.

## Outcome

`npm test` — 34 passing, no dependencies added. The suite is small, but it covers exactly the
code where a silent mistake would be hardest to notice: a hash that's subtly wrong, a contrast
ratio that passes when it shouldn't, a markdown renderer that lets a script through. Everything
else on the site is React and Tailwind, where the browser tells me immediately when it's wrong.

The lesson: a test I ran once in a temp folder is not a test, it's a memory. Yesterday's 31 CSV
cases were exactly that until this morning.
