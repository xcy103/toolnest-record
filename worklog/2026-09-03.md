## Catch-Up Work

### 1. Exact Dimensions and Aspect Ratio

Added `/image-resizer` for PNG, JPEG and WebP images. Width and height can be edited independently,
or linked to the original image's aspect ratio. The linked dimension is calculated from the
original dimensions, avoiding accumulated rounding error from repeatedly resizing an already
rounded value. Each resulting dimension is at least one pixel.

### 2. Browser Processing and Limits

Added a shared image-processing module and client component for the resizer and format converter.
The browser decodes the selected file and draws it at the requested dimensions before exporting.
Input files are limited to 20 MB; decoded source and output dimensions are limited to 8192 pixels
per side and 16,777,216 pixels total. Invalid dimensions disable processing.

Changing settings or selecting a new file removes the old download immediately. Request tokens
prevent older asynchronous reads or exports from replacing a newer selection. Object URLs are
released when replaced and when leaving the page, and canvas memory is released after encoding.

### 3. Interface and Integration

The page has labelled width/height controls, an aspect-ratio checkbox, original and result previews,
output format selection, dimensions, file sizes and a download with the correct extension.
English and Chinese pages are registered in the Image category and directory, with localized
metadata, JSON-LD and sitemap entries.

### 4. Verification

- A real 120 × 80 transparent PNG was resized to 60 × 40 with the aspect ratio locked.
- With the lock disabled, the same source produced a 90 × 20 result.
- Zero width disabled processing and removed the previous download link.
- The downloaded PNG was independently decoded with the existing Sharp package: dimensions were
  60 × 40 and the corner pixel remained transparent.
- A corrupt PNG showed a decoding error and cleared the old result; a valid WebP subsequently loaded
  and exported successfully.
- Phone-width screenshots showed readable controls and previews without horizontal overflow.

The combined image-tool change passed 83 unit tests, lint without warnings, and a production build
with 105 static pages. Both localized resizer routes returned HTTP 200 and appeared in the sitemap.
