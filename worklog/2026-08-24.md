# Work Log · August 24, 2026 (Monday)

**Hours:** ~4.5

## Overview

Back to building after the About and Privacy pages. Today's tool was an **HTML entity encoder /
decoder**, the next small item from the backlog and a natural addition to the Encoding category.
It escapes text so characters like `<`, `>`, `&` and quotes can be shown safely in HTML, and it
decodes common entities back to readable text. This brings the site to 29 tools.

## Today's Work

### 1. Scope: Text Conversion, Not Sanitizing

The first decision was wording and scope. This tool converts text representations; it is not an
HTML sanitizer and should not claim to make unsafe markup safe to render. If someone decodes
`&lt;script&gt;`, the page shows `<script>` as text in a textarea — it does not inject it into the
page as HTML. That distinction matters because "escape HTML" can sound like a security promise if
the page is careless.

Encoding is deliberately focused on the five structural characters: `&`, `<`, `>`, `"` and `'`.
Everything else, including Chinese, emoji and accented characters, stays readable. Turning every
non-ASCII character into a numeric entity would make the output uglier without helping the common
use case.

### 2. The Library

Added `lib/html-entities.ts` with two small functions: `encodeHtmlEntities` and
`decodeHtmlEntities`. Encoding is ordered so `&` is handled first; otherwise a generated `&lt;`
can be escaped again into `&amp;lt;`. Decoding supports the common named entities the tool needs
(`amp`, `lt`, `gt`, `quot`, `apos`, `nbsp`, `copy`, `reg`, `trade`) plus decimal and hexadecimal
numeric entities such as `&#169;` and `&#x1f600;`.

Unknown or malformed entities are left unchanged. That is safer than guessing, and it matches how
a text utility should behave: don't destroy input just because one entity name is unfamiliar.

### 3. Testing

Added `lib/html-entities.test.ts`. The tests cover encoding the five structural characters,
leaving normal Unicode readable, decoding named/decimal/hex entities, preserving unknown and
malformed entities, and decoding one layer at a time: `&amp;lt;` becomes `&lt;`, not `<`.

That last test is important because recursive decoding can surprise users and make it harder to
understand what the tool just did.

### 4. Page and Wiring

Built `/html-entities` as a bilingual Client Component with encode/decode tabs, an example button,
input and output panels, and copy support. Added the per-tool `layout.tsx` so the page gets its
own title, description, canonical, hreflang links and JSON-LD structured data. Registered it in
`lib/tools.ts`, which automatically brought it into the Encode category, `/tools`, search and the
sitemap.

## Outcome

29 tools live in the codebase. The lesson was scope discipline again: a small HTML entity tool is
useful precisely because it makes a limited promise and keeps decoded output as text.
