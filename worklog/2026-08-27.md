# Work Log · August 27, 2026 (Thursday)

**Hours:** ~4.5

## Overview

Today's tool was a focused **Unix Timestamp Converter**. The existing timezone page already had a
timestamp section, but it shares the page with multi-timezone comparison. This new page does one
job directly: convert Unix seconds or milliseconds to readable dates, ISO 8601, local time and UTC,
and convert a local date/time back to both timestamp units. This brings ToolNest to 32 tools.

## Today's Work

### 1. Why a Separate Tool

The product decision was to avoid making the existing timezone page heavier. People searching for
"Unix timestamp converter" usually want a fast answer to one of two questions: what date is this
number, or what number is this date? They should not have to parse a larger timezone utility to get
there.

So `/unix-timestamp` is intentionally narrower than `/timezone`: no city table, no timezone list,
just the timestamp, date, ISO and local/UTC views.

### 2. Seconds vs Milliseconds

The main trap is unit confusion. Unix timestamps are often seconds, while JavaScript uses
milliseconds. A 10-digit number and a 13-digit number can both look plausible, but choosing the
wrong unit sends the result to 1970 or far into the future.

The page makes the unit explicit with Seconds / Milliseconds controls. Switching units preserves
the same instant rather than reinterpreting the same raw number, so a user can safely move between
the two representations.

### 3. Library and Validation

Added `lib/timestamp.ts` with strict parsing:

- Empty input is a neutral state.
- Decimals and non-numeric values are rejected.
- Values must be safe integers.
- The final millisecond value must be inside JavaScript's valid `Date` range.
- Negative timestamps are allowed, because dates before 1970 are valid.

The output helpers use `Math.floor(ms / 1000)` for Unix seconds so negative millisecond values map
to the previous Unix second correctly. `Math.trunc` would make `-1ms` become `0s`, which is not the
right instant.

### 4. Page and Wiring

Built the page as a Client Component because it uses local state, `datetime-local`, and a client-only
"Use now" initialization to avoid a server/client time mismatch. Added the usual Server Component
`layout.tsx` for metadata and JSON-LD, then registered the tool in `lib/tools.ts` under the Time
category. English and Chinese messages cover the tool name, description, controls, empty states and
validation errors.

### 5. Verification

Added `lib/timestamp.test.ts` for seconds, milliseconds, negative timestamps, invalid input,
out-of-range values and formatting back to Unix seconds/milliseconds. Then ran the full project
checks:

- `npm test` — 60 passing.
- `npm run lint` — clean.
- `npm run build` — clean, 93 static pages.

## Outcome

The Time category now has a dedicated Unix timestamp tool instead of burying that workflow inside
the timezone converter. The lesson of the day was that timestamp tools are mostly about preventing
unit mistakes: seconds and milliseconds need to be visible, switchable and tested.
