# Work Log · August 8, 2026 (Saturday)

**Hours:** ~4.5

## Overview

Second color tool: a WCAG contrast checker. Pick a text color and a background, and it reports
the contrast ratio and whether it passes the accessibility thresholds (AA and AAA, for normal
and large text). Useful, and a natural pairing with yesterday's converter — so today also
included a small refactor to share code between the two.

## Today's Work

### 1. Refactor First: A Shared Color Module

Yesterday's converter had the color math (hex parsing, RGB↔HSL) inline. The contrast checker
needs the same hex parsing, and adds luminance and ratio math. Rather than copy-paste, I
pulled all of it into a `lib/color.ts` module — `parseHex`, `rgbToHex`, `rgbToHsl`,
`hslToRgb`, plus the new `relativeLuminance` and `contrastRatio` — and refactored the
converter to import from it. Two consumers is exactly the point at which sharing beats
duplicating, and doing the extraction *before* adding the second tool kept the math in one
place from the start. Verified the converter still works after the change; it's the kind of
refactor where an untested regression would be easy.

### 2. The WCAG Math

The contrast ratio isn't a naive difference of colors — it's defined on **relative
luminance**. Each channel is normalized to 0–1, linearized with the sRGB gamma curve (the
piecewise formula with the 0.03928 threshold), then combined with the luminance weights
(0.2126 R, 0.7152 G, 0.0722 B) that reflect how bright the human eye perceives each primary.
The ratio is then (lighter + 0.05) / (darker + 0.05), which ranges from 1:1 (identical) to
21:1 (black on white).

I verified the endpoints and boundaries before building: black on white is exactly 21.00, the
ratio is symmetric (swapping text and background doesn't change it), a color against itself is
1.00, and `#767676` on white comes out 4.54 — right at the AA-normal boundary of 4.5, which is
the classic "is this gray text legal?" case.

### 3. The Thresholds and the Preview

There are four pass/fail checks, because WCAG has two conformance levels crossed with two text
sizes: AA needs 4.5 (normal) / 3.0 (large), AAA needs 7.0 (normal) / 4.5 (large). The tool
shows all four as colored pass/fail chips. Above them is a **live preview** — the actual text
color on the actual background, in both a normal and a large weight — because a number is
abstract but seeing the text legible (or not) is immediate. The default of near-black on white
lands at 17.74, passing everything.

### 4. Verification

Unit-tested the ratio math (endpoints, symmetry, the 4.5 boundary), lint + build (65 static
pages), and served both locales: translated labels, the ratio and AA/AAA chips render, no
English leaks into the Chinese page, and — the regression check — the refactored converter
still works. The Color category now holds two tools, and search finds the checker in both
languages.

## Outcome

Twenty-one tools now. Two lessons worth keeping: the second user of a piece of logic is the
signal to extract it (and do it before writing the second user, not after it rots), and
accessibility contrast is a perceptual formula, not a numeric color distance — luminance
weighting and gamma linearization are the whole point.
