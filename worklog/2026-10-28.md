## Completed Work

- Reviewed find/replace matching and highlight-index behavior.
- Identified ASCII word boundaries as unsuitable for standalone Chinese text and many
  accented-letter words.
- Defined whole-word boundaries using Unicode letters, numbers, combining marks and
  underscores, with explicit lookarounds around the grouped search expression.
- Enabled Unicode regular-expression mode for whole-word searches only. Ordinary
  non-whole-word literal/regex behavior remains unchanged.
- Replaced manual empty-match advancement with native matchAll iteration, which handles
  Unicode code points while retaining UTF-16 offsets used by the highlight preview.
- Added four regression tests covering Chinese, accented and combining-mark text,
  underscore/digit adjacency, punctuation-bearing tokens and Unicode zero-length offsets.
- This is character-boundary matching, not dictionary-based Chinese word segmentation.
  Regex searches in whole-word mode now follow Unicode-mode regex syntax.

## Learning Notes

- Whole-word semantics need an explicit character policy; ASCII boundaries do not cover
  multilingual text.
- Combining marks belong with adjacent letters when deciding whether a word continues.
- Unicode iteration advances by code point, while DOM/string highlight offsets use UTF-16
  code units. Native APIs retain the correct distinction.
