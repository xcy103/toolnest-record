# Work Log · August 4, 2026 (Tuesday)

**Hours:** ~4.5

## Overview

Second tool of Wave 3 (developer): a regex tester. Enter a pattern and flags, paste some
text, and see the matches highlighted live with their capture groups listed. Regex is
something developers write constantly and get wrong constantly, so a fast "does this pattern
actually match what I think?" tool earns its place.

## Today's Work

### 1. Design

Three inputs — the pattern, a set of flag checkboxes (g / i / m / s / u), and the test
string — and two outputs: the test string with every match highlighted inline, and a list of
matches below with each match's capture groups. Live via `useMemo`, no button to press.
Building on the browser's own `RegExp` means the engine is exactly the one the developer's
JavaScript will use, which is the point.

### 2. The Two Traps

Regex tooling has two classic ways to break, and I made sure to handle both:

- **Invalid patterns.** A half-typed pattern like `(` is a syntax error. `new RegExp` throws,
  so the whole thing is wrapped in try/catch and surfaces the engine's own message ("Unterminated
  group") rather than crashing the page.
- **Zero-length matches.** A pattern like `a*` or an empty pattern matches the empty string at
  every position. Naive iteration with `exec` in a loop hangs forever because `lastIndex`
  never advances. I enumerate with `matchAll`, and after any empty match nudge `lastIndex`
  forward by one — and in the highlighter I skip zero-length matches so they don't produce
  empty `<mark>` tags. I explicitly tested `a*` and `""` to confirm no infinite loop.

### 3. Highlighting

To highlight, I force the global flag on internally (so I can enumerate all matches even if
the user didn't type `g`), then walk the matches building an array of text spans and `<mark>`
elements. Overlap and zero-length guards keep the segments clean.

### 4. Verification

Tested the matcher in isolation across the cases that matter: `\d+` finding multiple numbers,
a two-group pattern reporting both captures, case-insensitive matching, a Unicode literal
(你好) matching twice, and the two traps above. Then lint + build and served both locales —
translated labels and flag descriptions, no English leaking into the Chinese page, listed
under Developer and on `/tools`.

## Outcome

Wave 3 has its second tool. The lesson was defensive: a regex tester's whole job is to run
untrusted patterns against text, so the failure modes — invalid syntax and pathological
zero-length matches — *are* the feature surface, not edge cases to bolt on later.
